## Bugs this phase found and fixed

Recorded because three of them were invisible to a green build.

1. **`.toolbar` on `NavigationSplitView` renders nothing on iPadOS 26.** All
   three expected buttons were missing, not just the intentionally-hidden
   Compare and Sort. With no keyboard input yet, cancelling the launch picker
   left no route back to it. Fixed by attaching the same
   `@ToolbarContentBuilder` content to the `detail` column under `#if os(iOS)`,
   leaving the macOS attachment untouched.
2. **The iPad player cropped ~63% of every clip in portrait.**
   `videoGravity = .resizeAspectFill` was inherited from macOS, where the
   window's aspect makes it nearly harmless. On an iPad detail pane (~0.65
   aspect) it fills the height and discards most of the width — a skier could
   leave the visible frame. Now `.resizeAspect` on iOS; macOS unchanged.
3. **Security scopes were released too eagerly.** The folder picker released
   the previous scope before knowing the new one was usable, so an ordinary
   mis-tap onto a video-less folder left the working library listed but
   silently unreadable. Scopes are now held in a `Set<URL>` for the session and
   released in `deinit`.
4. **`INFOPLIST_KEY_UIFileSharingEnabled` is not a real Xcode setting.** It
   reaches `-showBuildSettings` convincingly and then silently vanishes. Only
   the `INFOPLIST_KEY_*` names in Xcode's `CoreBuildSystem.xcspec` are honoured.
   Now set via a partial `iPad-Info.plist` merged through `INFOPLIST_FILE`.
5. **The Xcode macOS target claimed the shipping bundle identifier** at a higher
   version, so merely building in Xcode registered a competing
   `ch.ski.video-viewer` with LaunchServices. Now `ch.ski.video-viewer.xcode`.
6. **The smoke test did not work on a fresh clone** — the gitignored
   `.xcodeproj` was never regenerated.

## Guards worth keeping

- **Before adding any `INFOPLIST_KEY_*`**, grep `/Applications/Xcode.app` for
  it, then confirm the key actually appears in the built plist. It reaches
  build settings either way.
- **`Shared/` means "compiles on both platforms."** `project.yml` has no
  `excludes:` and should stay that way. `ComparisonView.swift` currently lives
  in `macOS/` *because* it depends on `OverlayPlayerView`; phase 5 moves it
  back once a UIKit overlay exists.
- Only the macOS target is on the routine path (`swift test`, `build_app.sh`).
  A `Shared/` file that references an AppKit type passes every habitual gate
  and fails only in `ipad-smoke.sh`. Run that script when touching `Shared/`.

## Not verified

- **The macOS toolbar.** `#if os(macOS)` compiles but nothing here renders it.
  The extracted `@ToolbarContentBuilder` was proven byte-identical to the old
  inline closure after dedent (52 lines each), so risk is low — but **open the
  Mac app once and confirm five toolbar buttons in this order: Compare, Sort,
  Google Drive, Find Athlete, Open Folder.**
- **Tapping any iPad control.** `simctl` has no input injection and `idb` is not
  installed. The rendered UI and the code paths behind the buttons are both
  verified; the hit-testing is not. XCUITest is the real answer and needs a
  UI-test target in `project.yml`.
- The Drive sheet's greyed-out Connect, and anything requiring a second tap.

## Carried forward

### Phase 4 (touch and keyboard input)

- `InertInputSource` emits nothing. Everything the UI advertises —
  `ContentView.swift`'s "↑/↓ clips · Page Up/Down athletes · ⌘F · Space · ←/→"
  hint row and `ViewerModel`'s "Paused · Space to play" status — is dead on
  iPad. Either wire the input or condition the copy.
- ⌘F/⌘O may already work with a hardware keyboard: `.keyboardShortcut` on a
  SwiftUI toolbar button is handled by SwiftUI, not by the app's key monitor.
  Unverified.
- **Add an XCUITest target.** It closes the tap gap and would have caught the
  toolbar bug automatically. `app.buttons["Open Folder…"].exists` is one line.
- Bookmark persistence: the picked folder must be re-picked after relaunch. The
  core stores **String paths**, not bookmarks — `ViewerModel.clientSecretsPath`,
  the `UserDefaults` writes, `SortingModel.sourcePath`/`namesPath`. Moving to
  `bookmarkData()` changes core public API.

### Phase 5 (Compare and Sort on iPad)

- Move `ComparisonView.swift` back to `Shared/` once a UIKit `OverlayPlayerView`
  exists. Verify `CALayer.compositingFilter` actually renders on iOS first — it
  compiles but Core Animation may not execute it.
- `NoSecondaryScreenPresenter.canPresent` must stay a per-platform **constant**.
  `ContentView` reads it while building `body` and the presenter is not
  observable, so a runtime-varying value would not update the toolbar.
- Fixed minimums that exceed an 11-inch iPad's 834pt portrait width:
  `SortingSheet.swift` (`minWidth: 820`) and `ComparisonView.swift`
  (`minWidth: 1000`).
- The toolbar is attached to the `detail` column, so it is absent in compact
  width (Slide Over, narrow Stage Manager) where the split view collapses onto
  the sidebar.
- Sort needs the AVFoundation media pipeline from phase 2 — `SortingSheet`
  compiles for iOS only because it takes `MediaPipeline` as a protocol; the sole
  implementation uses `Process`.

### Phase 6 (Drive auth)

- **`UnavailableOAuthPresenter` gates only the interactive leg.** The Keychain
  read and a network POST to Google's token endpoint happen *before* the
  presenter is consulted, so a stored refresh token would open a Drive library
  on a platform where Drive is declared unavailable. Unreachable today (no
  `keychain-access-groups` entitlement), reachable the moment phase 6 adds one.
- `pickFile` is deliberately unscoped. `ViewerModel.chooseClientSecretsFile`
  discards the URL and stores `url.path`, rebuilding it later possibly in
  another process — no per-URL scope survives that. Needs a security-scoped
  bookmark in the core.
- `GoogleDriveSheet.swift` tells iPad users the token is "stored in your macOS
  Keychain", and hard-codes `.frame(width: 560)`, which exceeds an iPad form
  sheet's ~540pt.
- Still open from phase 1: `DriveMedia.streamingURL` embeds the OAuth access
  token as a URL query parameter, and Google has been retiring that.

## Machine hygiene, not a code defect

Building in Xcode before the identifier fix left competing
`ch.ski.video-viewer` LaunchServices registrations at version 8, which outrank
the real version-7 app. If the Dock or `open -b ch.ski.video-viewer` resolves to
the wrong bundle, unregister them:

```
/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister \
  -u /private/tmp/macclean/Build/Products/Debug/SkiVideoViewer.app
```

`run.sh` uses `open -n <path>` and is unaffected.
